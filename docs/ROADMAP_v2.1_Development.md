# 🗺️ Roadmap: Разработка Figma Direct Importer v2.1

Этот документ фиксирует стратегию перехода от монолитного плагина (v1.1.1) к профессиональной модульной системе (v2.1).

## 🚀 Стратегия разработки
1.  **Git Flow:** Вся разработка ведется в отдельной ветке `feature/v2.1-overhaul`. Основная ветка (`main`) остается стабильной с версией v1.1.1.
2.  **Технический стек:** Строго **uGUI** (Canvas System). Использование UI Toolkit в данной версии не планируется для сохранения обратной совместимости и предсказуемости верстки.
3.  **Параллельное сосуществование:** Новая версия разрабатывается в новой папке. Старый файл `FigmaDirectImporter.cs` (v1.1.1) **не удаляется** до полного завершения и тестирования v2.1.
4.  **Изоляция (Namespaces):** Весь код v2.1 оборачивается в пространство имен `FigmaImporter.V2`, чтобы избежать конфликтов имен классов с v1.1.1.

---

## 📂 Структура проекта (UPM Package)
Для обеспечения независимости инструмента от конкретной игры, проект переведен на стандарт Unity Package Manager:

`Packages/com.figmaimporter.v2/`
├── `Editor/`                 # Логика импорта (только для Editor)
│   ├── `Core/`               # Парсинг и Генерация (FigmaParser.cs)
│   ├── `Handlers/`           # Обработчики компонентов (InteractiveHandler.cs [NEW])
│   ├── `UI/`                 # Интерфейс плагина (FigmaImporterWindow.cs)
│   └── `Serialization/`      # JSON DTO и модели
└── `Runtime/`                # Скрипты для финального билда
    ├── `FigmaElement.cs`     # Паспорт объекта (ID, Hash)
    └── `Data/`               # Настройки (FigmaImporterSettings.cs)

## 🏛️ Архитектурные принципы (от Cloud Dragonborn)
*   **Separation of Concerns:** Окно импорта не должно знать, как парсится JSON. Парсер не должен знать, как создается GameObject.
*   **Performance First:** Операции поиска ассетов (`AssetDatabase`) должны быть кэшированы в Dictionary на старте процесса.
*   **Safety:** Любая потенциально опасная операция (например, изменение структуры префаба) должна поддерживать `Undo.RecordObject`.
