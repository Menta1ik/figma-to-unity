# Можно ли управление адаптивностью вынести в настройки? Допустим, включить-выключить, нужно мне соблюдать адаптивность или не нужно? Вот такого плана.

Да, это правильная идея — и архитектурно чистая. Вот как это реализовать.

## Что добавить в `FigmaImporterSettings`

```csharp
[Header("Adaptive Layout")]
public bool enableConstraintsTranslation = false; // выкл. по умолчанию — не ломает старые проекты
public AdaptiveScaleMode canvasScaleMode = AdaptiveScaleMode.None;
public Vector2 referenceResolution = new Vector2(1920, 1080);

[Range(0f, 1f)]
public float matchWidthOrHeight = 0.5f; // 0 = по ширине, 1 = по высоте, 0.5 = среднее
```

```csharp
public enum AdaptiveScaleMode
{
    None,                // не трогать CanvasScaler — разработчик настроит сам
    ScaleWithScreenSize, // масштабировать Canvas под референсное разрешение
    ConstantPixelSize    // фиксированный размер, без масштабирования
}
```


## Как это ложится в `TransformHandler`

Сейчас `TransformHandler` ничего не знает о настройках. Нужно пробросить их через `FigmaHandlerContext` (он уже передаётся везде):

```csharp
// В FigmaHandlerContext — уже есть Settings, просто используем его
public void Apply(FigmaNode node, FigmaElement target, FigmaHandlerContext context)
{
    var rect = target.GetComponent<RectTransform>();
    
    // ... текущая логика позиционирования ...
    
    // Новое: constraints только если включено в настройках
    if (context.Settings != null && context.Settings.enableConstraintsTranslation)
    {
        ApplyConstraints(node, rect);
    }
    // Иначе — оставляем anchor (0.5, 0.5) как сейчас
}
```


## Как это ложится в `FigmaParser` (CanvasScaler)

```csharp
// В конце ProcessFileAsync, после построения иерархии:
if (Settings != null && Settings.canvasScaleMode != AdaptiveScaleMode.None)
{
    ApplyCanvasScaler(rootCanvas);
}

private void ApplyCanvasScaler(Transform rootCanvas)
{
    // Ищем Canvas вверх по иерархии
    var canvas = rootCanvas.GetComponentInParent<Canvas>();
    if (canvas == null) return;
    
    var scaler = canvas.GetComponent<CanvasScaler>();
    if (scaler == null) scaler = canvas.gameObject.AddComponent<CanvasScaler>();

    switch (Settings.canvasScaleMode)
    {
        case AdaptiveScaleMode.ScaleWithScreenSize:
            scaler.uiScaleMode = CanvasScaler.ScaleMode.ScaleWithScreenSize;
            scaler.referenceResolution = Settings.referenceResolution;
            scaler.matchWidthOrHeight = Settings.matchWidthOrHeight;
            break;
        case AdaptiveScaleMode.ConstantPixelSize:
            scaler.uiScaleMode = CanvasScaler.ScaleMode.ConstantPixelSize;
            break;
    }
}
```


## Как это выглядит в Editor UI

В `FigmaImporterWindow` добавить секцию:

```csharp
EditorGUILayout.LabelField("Adaptive Layout", EditorStyles.boldLabel);

settings.enableConstraintsTranslation = EditorGUILayout.Toggle(
    new GUIContent("Translate Constraints", 
        "Maps Figma constraints (LEFT, RIGHT, SCALE...) to Unity RectTransform anchors"),
    settings.enableConstraintsTranslation
);

settings.canvasScaleMode = (AdaptiveScaleMode)EditorGUILayout.EnumPopup(
    new GUIContent("Canvas Scale Mode", 
        "None = don't touch CanvasScaler, ScaleWithScreenSize = auto-scale to reference resolution"),
    settings.canvasScaleMode
);

if (settings.canvasScaleMode == AdaptiveScaleMode.ScaleWithScreenSize)
{
    EditorGUI.indentLevel++;
    settings.referenceResolution = EditorGUILayout.Vector2Field("Reference Resolution", settings.referenceResolution);
    settings.matchWidthOrHeight = EditorGUILayout.Slider("Match Width/Height", settings.matchWidthOrHeight, 0f, 1f);
    EditorGUI.indentLevel--;
}
```


## Три режима работы — итог

| Режим | Constraints | CanvasScaler | Когда использовать |
| :-- | :-- | :-- | :-- |
| **Off / Off** | ❌ | ❌ | Прототип, один экран, разработчик настроит сам |
| **Off / ScaleWithScreenSize** | ❌ | ✅ | Мобильная игра с фиксированным макетом — Canvas масштабируется целиком |
| **On / ScaleWithScreenSize** | ✅ | ✅ | Полноценный адаптивный UI, элементы привязаны по Figma constraints |

## Главное преимущество такого подхода

По умолчанию оба флага `false` — **ничего не ломается в существующих проектах**. Разработчик явно включает адаптивность когда она нужна. Это правильная UX-логика для инструмента: не делай умных вещей молча, дай пользователю контроль.
