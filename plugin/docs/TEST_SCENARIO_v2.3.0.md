# Сценарий проверки Figma Importer v2.3.0 (Stable)

Этот документ описывает шаги для полной проверки работоспособности плагина в версии v2.3.0 (Stable).

## 🛠 Подготовка
1. **Очистка данных**: Удалены старые спрайты и кэшированные настройки для "чистого" теста.
2. **Перезагрузка Unity**: Убедитесь, что все скрипты скомпилированы без ошибок.

---

## 📋 Шаги проверки

### Шаг 1: Инициализация настроек
1. В окне Project нажмите `Right Click -> Create -> Figma Importer -> Importer Settings`.
2. Назовите файл `GlobalFigmaSettings`.
3. В инспекторе настройте пути для спрайтов и префабов.

### Шаг 2: Диагностика (Health Check)
1. Откройте `Figma Importer -> Diagnostics -> Health Check`.
2. Нажмите **Run All Tests**.
3. **Ожидаемый результат**: Все тесты (Fonts, Layout, Soft-Delete) должны пройти успешно (зеленые галочки).

### Шаг 3: Синхронизация (Cloud Sync)
1. Откройте окно `Figma Importer / Sync & Reskin Dashboard`.
2. Введите **Access Token** и **File ID**.
3. Нажмите **🚀 SYNC & GENERATE UI**.

**Ожидаемый результат:**
- Построена иерархия объектов.
- Изображения скачаны параллельно (проверьте консоль на наличие логов параллельной загрузки).

### Шаг 4: Проверка Auto Layout & 9-Slice
1. Выберите объект, который в Figma имел Auto Layout. Убедитесь, что в Unity добавлены `HorizontalLayoutGroup` / `VerticalLayoutGroup`.
2. Найдите спрайт с суффиксом `_9slice`. Убедитесь, что `Image Type` установлен в `Sliced`, а границы `SpriteBorder` не нулевые.

### Шаг 5: Проверка Soft-Delete
1. Переименуйте или удалите слой в Figma.
2. Запустите повторную синхронизацию.
3. **Ожидаемый результат**: Старый объект в Unity не удалился, а стал выключенным и получил компонент `FigmaOrphanedElement`.

---

## 🚦 Критерии успеха
- [x] Диагностика проходит без ошибок.
- [x] Параллельная загрузка сокращает время импорта.
- [x] Auto Layout корректно транслирует отступы.
- [x] При ре-синке не пропадают ссылки на компоненты (благодаря Soft-Delete).
