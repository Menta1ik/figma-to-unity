## Сценарий 1: Макет полностью без Auto Layout

Все ноды — просто Frame/Rectangle/Text с абсолютными координатами. `LayoutHandler.CanHandle()` вернёт `false` для всех нод, и в игру входит **только `TransformHandler`**.

Что он делает:

```
Figma absoluteBoundingBox (x, y, width, height)
→ RectTransform.anchoredPosition = (x + width/2, -(y + height/2))
→ RectTransform.sizeDelta = (width, height)
→ anchorMin = anchorMax = (0.5, 0.5)  // центр — всегда
```

**Плагин не сломается.** Все элементы перенесутся, текст, цвета, изображения — всё будет на месте. Но UI будет **заморожен** — pixel-perfect на том разрешении, под которое делался макет. На другом разрешении элементы начнут уезжать, потому что anchor `(0.5, 0.5)` означает "я отмерен от центра Canvas", и при изменении размера Canvas каждый объект двигается по-своему.

Визуально это выглядит так:

```
Макет 1920×1080:          Телефон 390×844:
┌──────────────────┐      ┌──────┐
│  [Кнопка]        │  →   │ [Кнопка смещена и обрезана]
│           [Иконка│      │
└──────────────────┘      └──────┘
```


## Сценарий 2: Смешанный макет (часть с Auto Layout, часть без)

Это самый частый реальный случай. Например: общий экран без Auto Layout, но внутри него — карточки с Auto Layout.

Здесь важно понимать что `LayoutHandler` и `TransformHandler` применяются **независимо к каждой ноде**. Нет конфликта — просто каждая нода получает то, что ей положено. Плагин не сломается.

Проблема только одна: если нода с Auto Layout находится внутри родителя без Auto Layout — её позиция будет абсолютной (от центра Canvas), и при изменении разрешения она уедет вместе с содержимым, которое внутри адаптируется корректно. То есть **контейнер едет, но внутренности перестраиваются правильно**.

## Что реально сломается / не сломается

| Ситуация | Плагин падает? | Визуальный результат |
| :-- | :-- | :-- |
| Макет полностью без Auto Layout | ❌ нет | Pixel-perfect на одном разрешении |
| Макет полностью с Auto Layout | ❌ нет | Адаптивно, но без constraints |
| Смешанный макет | ❌ нет | Частично адаптивно |
| Нода с `isMask` без Auto Layout | ❌ нет | Маска применится корректно |
| Текст без шрифта в маппинге | ❌ нет | Fallback на GlobalFont |
| Текст без шрифта + GlobalFont = null | ✅ **блокируется** | DisplayDialog, импорт остановлен |

## Практический вывод

Для продакшена с одним целевым разрешением (например мобильная игра только под iPhone 14 или PC-игра 1920×1080) — **плагин работает корректно уже сейчас** без constraints. `CanvasScaler` в режиме `ScaleWithScreenSize` с референсным разрешением макета закроет большинство кейсов: Canvas будет масштабироваться целиком, и pixel-perfect сохранится.

Constraints нужны только если UI должен **структурно перестраиваться** — кнопка прижата к правому краю на любом экране, панель растягивается на всю ширину, элементы в нижнем баре всегда у нижнего края. Без этого `CanvasScaler` просто масштабирует всё пропорционально, что для многих проектов достаточно.
