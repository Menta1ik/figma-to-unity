# Расскажи мне про адаптивность в контексте этого плагина.

Отличный вопрос, и здесь есть что сказать — потому что адаптивность в контексте Figma-to-Unity это принципиально другая задача, чем в вебе.

## Что такое "адаптивность" в Unity UI

В вебе адаптивность = CSS media queries + flexbox. В Unity uGUI это целая система из нескольких независимых механизмов, которые работают вместе:

- **`CanvasScaler`** — масштабирует весь Canvas под целевое разрешение
- **`RectTransform` anchors** — определяют как объект двигается/тянется при изменении родителя
- **`LayoutGroup`** — автоматически расставляет дочерние элементы
- **`ContentSizeFitter`** — подгоняет размер под содержимое
- **`AspectRatioFitter`** — сохраняет пропорции


## Что плагин делает сейчас

Смотря на код `TransformHandler` и `LayoutHandler` — плагин работает в **двух режимах** в зависимости от того, есть ли у ноды Auto Layout:

**Нода без Auto Layout** → `TransformHandler` вычисляет абсолютные координаты через `AbsoluteBox` и ставит фиксированные `anchoredPosition` + `sizeDelta`. Это **pixel-perfect, но не адаптивно**. Объект будет стоять на той же пиксельной позиции независимо от разрешения экрана.

**Нода с Auto Layout** → `LayoutHandler` вешает `HorizontalLayoutGroup` / `VerticalLayoutGroup` + `ContentSizeFitter`. Это **уже адаптивно** — дочерние элементы перестраиваются при изменении контейнера.

## Главная проблема: anchors не транслируются

Это самый критичный пробел в плагине. В Figma у каждого элемента есть `constraints` — правила привязки к родителю:

```
constraints: {
  horizontal: "LEFT" | "RIGHT" | "CENTER" | "LEFT_RIGHT" | "SCALE",
  vertical: "TOP" | "BOTTOM" | "CENTER" | "TOP_BOTTOM" | "SCALE"
}
```

В Unity это напрямую маппится на `RectTransform.anchorMin` и `anchorMax`:


| Figma constraint | Unity anchors |
| :-- | :-- |
| `LEFT` | anchorMin.x = 0, anchorMax.x = 0 |
| `RIGHT` | anchorMin.x = 1, anchorMax.x = 1 |
| `CENTER` | anchorMin.x = 0.5, anchorMax.x = 0.5 |
| `LEFT_RIGHT` (stretch) | anchorMin.x = 0, anchorMax.x = 1 |
| `SCALE` | anchorMin.x = left%, anchorMax.x = right% |
| `TOP` | anchorMin.y = 1, anchorMax.y = 1 |
| `BOTTOM` | anchorMin.y = 0, anchorMax.y = 0 |
| `TOP_BOTTOM` (stretch) | anchorMin.y = 0, anchorMax.y = 1 |

Сейчас `TransformHandler` ставит anchors в центр (`0.5, 0.5`) для всех нод. Это значит что кнопка, которая в Figma привязана к правому краю экрана, после импорта при смене разрешения уедет не туда.

## Что нужно добавить

### 1. Трансляция `constraints` в anchors

В `FigmaDataModels.cs` нужно добавить поле (если ещё нет):

```csharp
public FigmaConstraints constraints; // { horizontal, vertical }
```

В `TransformHandler.Apply` после установки `sizeDelta` добавить:

```csharp
private void ApplyConstraints(FigmaNode node, RectTransform rect)
{
    if (node.constraints == null) return;

    float xMin, xMax, yMin, yMax;

    switch (node.constraints.horizontal)
    {
        case "LEFT":       xMin = 0; xMax = 0; break;
        case "RIGHT":      xMin = 1; xMax = 1; break;
        case "CENTER":     xMin = 0.5f; xMax = 0.5f; break;
        case "LEFT_RIGHT": xMin = 0; xMax = 1; break; // stretch
        case "SCALE":
            // Рассчитать как % от ширины родителя
            float parentW = rect.parent?.GetComponent<RectTransform>()?.rect.width ?? 1;
            xMin = node.absoluteBoundingBox.x / parentW;
            xMax = (node.absoluteBoundingBox.x + node.absoluteBoundingBox.width) / parentW;
            break;
        default: xMin = 0.5f; xMax = 0.5f; break;
    }

    // Vertical (в Unity Y инвертирован относительно Figma)
    switch (node.constraints.vertical)
    {
        case "TOP":        yMin = 1; yMax = 1; break;
        case "BOTTOM":     yMin = 0; yMax = 0; break;
        case "CENTER":     yMin = 0.5f; yMax = 0.5f; break;
        case "TOP_BOTTOM": yMin = 0; yMax = 1; break; // stretch
        case "SCALE":
            float parentH = rect.parent?.GetComponent<RectTransform>()?.rect.height ?? 1;
            yMin = node.absoluteBoundingBox.y / parentH;
            yMax = (node.absoluteBoundingBox.y + node.absoluteBoundingBox.height) / parentH;
            break;
        default: yMin = 1; yMax = 1; break;
    }

    rect.anchorMin = new Vector2(xMin, yMin);
    rect.anchorMax = new Vector2(xMax, yMax);
    
    // При stretch нужно пересчитать sizeDelta на отступы (offset) вместо размера
    if (xMin != xMax || yMin != yMax)
    {
        RecalculateOffsets(node, rect);
    }
}
```


### 2. Stretch требует пересчёта offsetMin/offsetMax

Когда anchors растянуты (`LEFT_RIGHT` или `TOP_BOTTOM`), `sizeDelta` перестаёт означать "размер" — оно становится "отступами от якорей". Это самая трикитная часть:

```csharp
private void RecalculateOffsets(FigmaNode node, RectTransform rect)
{
    // При stretch: offsetMin/offsetMax = отступы от краёв родителя
    // offsetMin.x = left padding, offsetMax.x = -right padding
    if (rect.anchorMin.x == 0 && rect.anchorMax.x == 1)
    {
        float parentW = ((RectTransform)rect.parent).rect.width;
        rect.offsetMin = new Vector2(node.absoluteBoundingBox.x - parentAbsX, rect.offsetMin.y);
        rect.offsetMax = new Vector2(-(parentW - node.absoluteBoundingBox.width - (node.absoluteBoundingBox.x - parentAbsX)), rect.offsetMax.y);
    }
    // Аналогично для Y
}
```


### 3. `CanvasScaler` и SafeArea

Плагин не настраивает `CanvasScaler` — это остаётся на разработчика. Хорошая практика: добавить в `FigmaImporterSettings` поле `referenceResolution` (например `1920x1080`) и после импорта автоматически выставлять:

```csharp
var scaler = rootCanvas.GetComponent<CanvasScaler>();
if (scaler != null && Settings.referenceResolution != Vector2.zero)
{
    scaler.uiScaleMode = CanvasScaler.ScaleMode.ScaleWithScreenSize;
    scaler.referenceResolution = Settings.referenceResolution;
    scaler.matchWidthOrHeight = 0.5f; // среднее между W и H
}
```


## Практический совет для дизайнеров

Чтобы плагин давал максимально адаптивный результат — нужно договориться с дизайнером о правилах в Figma:

1. **Использовать Auto Layout везде где возможно** — это уже правильно транслируется в `LayoutGroup`
2. **Явно выставлять `constraints`** для всех элементов (не оставлять дефолтный `LEFT/TOP`)
3. **Главный экран делать в `1920×1080`** — тогда `SCALE` constraints будут считаться корректно
4. **Не использовать абсолютное позиционирование** для элементов, которые должны адаптироваться

## Что это даст после реализации

Сейчас плагин даёт **pixel-perfect на одном разрешении**. После реализации трансляции `constraints` — UI будет корректно адаптироваться к любому соотношению сторон: кнопки у правого края останутся у правого края, растянутые панели будут растягиваться, центрированные элементы будут оставаться по центру. Это финальный шаг от "инструмента для переноса макета" к "полноценному UI-пайплайну".
