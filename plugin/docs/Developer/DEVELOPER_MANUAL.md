# 📖 Полное руководство разработчика: Figma Importer v2.5.1

Данное руководство содержит исчерпывающую информацию по настройке и эксплуатации системы импорта UI из Figma в Unity uGUI. 

---

## 🛠 1. Установка и зависимости

Плагин работает как автономный **UPM-пакет**. 

### Требования:
*   **Unity 2021.3 LTS** или выше.
*   **TextMeshPro**: должен быть установлен в проекте (Window -> TextMeshPro -> Import TMP Essential Resources).

### Шаги по установке через Git:
1.  Откройте **Window -> Package Manager**.
2.  Нажмите кнопку **+** (Add) и выберите **Add package from git URL...**.
3.  Вставьте строку: `https://github.com/Menta1ik/figma-to-unity.git?path=plugin#v2.5.1`
4.  Нажмите **Add**. Unity загрузит плагин и автоматически добавит зависимости (Newtonsoft JSON).

## ⚙️ 2. Шаг 0: Создание конфигурационных ассетов

Прежде чем открывать окно импортера, необходимо создать два файла данных в вашем проекте (`Assets/`):

### А. FigmaImporterSettings (Общие настройки)
1.  В окне **Project** нажмите правую кнопку мыши -> **Create -> Figma Importer -> Settings**.
2.  Назовите ассет, например, `MyProjectSettings`.
3.  **Настройка путей (Asset Paths):**
    *   `Base Sprites Path`: Куда сохранять скачанные картинки (например, `UI/Sprites`).
    *   `Base Prefabs Path`: Куда сохранять готовые префабы (например, `UI/Prefabs`).
4.  **Политика Non-Destructive:**
    *   `Preserve Unity Names`: Если включено, плагин не будет менять имена объектов, которые вы переименовали вручную в Unity.
    *   `Preserve Manual Components`: Если включено, плагин не будет удалять компоненты (скрипты, анимации), добавленные вами поверх импортированных объектов.

### Б. Логирование (Logging) — *Новое в v2.5.1*
*   `Log Level`: Управляет объёмом вывода в Console Unity.
    *   `Silent` — никаких логов. Полезно при автоматизации/CI.
    *   `Minimal` (по умолчанию) — только вехи: начало/конец синхронизации, итоги загрузки изображений, сохранение префаба, ошибки.
    *   `Verbose` — детальный вывод по каждой ноде: какой хендлер сработал, какой шрифт заменён, какой тип маски назначен. Для отладки.

### В. Экспорт изображений (Image Export) — *Новое в v2.5.1*
*   `Image Export Scale`: Коэффициент масштабирования при загрузке изображений из Figma API. Диапазон: 0.5–4x, по умолчанию **2x**.
    *   `1` = оригинальный размер из Figma.
    *   `2` = ретина-качество (рекомендуется для мобильных проектов).
    *   `3–4` = высокое разрешение для десктопа/планшетов.

### Г. Адаптивность (Adaptive Layout)
Настройки адаптивности позволяют плагину автоматически настраивать `RectTransform` и корневой `Canvas`:
*   `Enable Constraints Translation`: При включении плагин переводит "Constraints" из Figma в анкоры (Anchors) и отступы (Offsets) Unity. Если выключено — используется абсолютное позиционирование.
*   `Canvas Scale Mode`: Определяет тип компонента `CanvasScaler` на корневом объекте:
    *   `Constant Pixel Size`: UI не меняет размер при изменении разрешения.
    *   `Scale With ScreenSize`: Самый частый режим. UI растягивается пропорционально.
*   `Reference Resolution`: Дизайнерское разрешение (например, 1920x1080).
*   `Match Width or Height`: Баланс масштабирования между шириной и высотой (0 — по ширине, 1 — по высоте).

---

### Г. FontMappingTable (Таблица шрифтов)
1.  Нажмите правую кнопку мыши -> **Create -> Figma Importer -> Font Mapping Table**.
2.  Этот ассет связывает имена шрифтов из Figma с вашими ассетами **TextMeshPro SDF**.
3.  Вы можете заполнить её вручную или использовать кнопку **Font Audit** в окне импортера для автоматического поиска используемых шрифтов.

## 🖥 3. Работа с окном Figma Importer

Откройте окно через меню: **Window -> Figma Importer -> Dashboard**.

### Блок 1: Connection & Config (Связь)
*   **Figma URL / File ID**: Вставьте полную ссылку на макет Figma или его ID (набор символов из URL).
*   **Single Node ID**: (Опционально) Если вам нужно обновить не весь файл, а только один экран — выделите его в Figma, нажмите правой кнопкой -> **Copy link** и вставьте сюда. Плагин сам вырежет ID ноды.
*   **Access Token (PAT)**: Ваш персональный токен Figma. Получается в настройках Figma (*Settings -> Personal access tokens*). Токен хранится в `SessionState` — он переживает перезагрузку домена (компиляцию скриптов), но никогда не сохраняется на диск и автоматически очищается при закрытии Unity.
*   **Importer Settings**: Перетащите сюда созданный ассет настроек из Шага 2А.

### Блок 2: Resources & Target (Ресурсы)
*   **Font Mapping**: Перетащите сюда таблицу шрифтов из Шага 2Б.
*   **Кнопка [Font Audit]**: Нажмите её, чтобы просканировать Figma-файл. В консоли появится список всех шрифтов. Если какого-то шрифта нет в таблице маппинга — плагин выдаст ошибку.
*   **Root Canvas**: Самое важное поле. Перетащите сюда объект **Canvas** из вашей сцены. Внутри него плагин будет строить UI.

### Блок 3: Sync & Generate (Запуск)
*   **Sync Images**: Включает/выключает скачивание картинок. Если вам нужно только поправить текст — выключите это для скорости.
*   **Force Update**: Если включено, плагин полностью пересоберет сцену с нуля, игнорируя существующие объекты и кэши.
*   **Image Export Scale** *(v2.5.1)*: Слайдер масштаба загружаемых изображений (0.5–4x). Значение берётся из `FigmaImporterSettings` и передаётся в Figma API при запросе рендера.
*   **Кнопка [🚀 RUN FULL SYNC]**: Запускает процесс.

## 🏗 4. Внутренняя архитектура и стабильность (v2.4+)

Начиная с версии **2.5.1**, в плагине реализована система **Stencil Guard**, предназначенная для предотвращения критических ошибок Unity `stencil mask depth > 8`.

### Основные компоненты v2.4:
*   **FigmaParser (Orchestrator)**: Теперь включает логику агрессивного «разглаживания» (flattening) иерархии перед каждым импортом.
*   **Stencil Guard**: Мониторит глубину вложенности масок. При достижении лимита (3 уровня) система автоматически переключает тип маски на `RectMask2D`, что гарантирует работоспособность UI даже в экстремально сложных макетах.
*   **Aggressive Flattening**: Логика `DismantleAllMaskContainers` находит все старые технические контейнеры `[Mask]` и переносит их содержимое обратно в основной поток иерархии перед началом синхронизации. Это обеспечивает идемпотентность процесса (результаты повторных импортов идентичны).

### Оптимизация производительности:
Для ускорения работы с огромными макетами используется система **IconCandidateCache**, минимизирующая рекурсивные проверки в `ImageHandler`.

## 🏗 5. Процесс синхронизации и результат

После нажатия кнопки происходит следующее:
1.  **Парсинг JSON**: Плагин запрашивает структуру макета.
2.  **Сборка иерархии**: На сцене создаются объекты. Каждому назначается компонент `FigmaElement` (не удаляйте его!).
3.  **Batch Image Sync**: Если включены картинки, плагин запрашивает их ссылками по 25 штук (в версии 2.3 это работает стабильно и без таймаутов).
4.  **Auto-Prefab**: Как только сборка завершена, плагин **мгновенно** сохраняет результат в префаб по пути из настроек и связывает объект на сцене с этим префабом.

## 🏷 6. Подготовка макета в Figma (Маркеры)

Чтобы автоматизировать создание кнопок и инпутов, добавляйте суффиксы к названиям слоев прямо в Figma:

| Маркер | Результат в Unity |
| :--- | :--- |
| `[Btn]` | Добавит компонент **Button** и настроит `Raycast Target`. |
| `[Input]` | Добавит компонент **TMP_InputField**. |
| `[Scroll]` | Создаст структуру **ScrollRect**. |
| `[Toggle]` | Добавит компонент **Toggle**. |

## 🆘 7. Решение проблем (Troubleshooting)

### Сцена пустая или объекты не видны:
1.  **Проверьте координаты**: Элементы могут быть смещены. Посмотрите в Hierarchy — если объекты есть, но их не видно, проверьте их `RectTransform`.
2.  **Удаление старого**: Если вы работали в версии 2.1 и сцена "сломалась", удалите старый Canvas и префабы, и сделайте **чистый импорт**.
3.  **Блокировка префаба**: Если объект в Unity является частью другого префаба, Unity может запретить плагину менять его структуру. Используйте **Unpack Prefab** перед синхронизацией, если планируете сильно менять структуру.

### Ошибка 400 Bad Request:
*   В версии 2.3 это практически исключено благодаря батчингу. Если ошибка осталась — проверьте стабильность интернета или валидность Access Token.

## 🔍 8. Диагностика и проверка состояния (Health Check)

Начиная с версии **2.5.1**, в плагин встроен инструмент автоматического аудита пайплайна. Если у вас возникли ошибки при импорте или верстка выглядит некорректно, первым делом запустите проверку.

### Как запустить:
1. Перейдите в меню: **Figma Importer -> Diagnostics -> Health Check (v2.5.1)**.
2. В открывшемся окне нажмите **Run Full Audit**.

### Что проверяет аудит:
*   **Architecture Integrity**: Проверяет наличие и доступность `ImageSyncService` и `PrefabManager`.
*   **Asmdef Verification**: Гарантирует, что Assembly Definition файлы настроены корректно и не вызывают циклических зависимостей.
*   **Font Validation**: Проверяет наличие глобального шрифта-заглушки.
*   **Auto Layout Translator**: Тестирует логику маппинга Auto Layout на мок-ноде.
*   **9-Slice Automation**: Проверяет корректность распознавания суффикса `_9slice`.
*   **Soft-Delete Enforcement**: Проверяет систему защиты от удаления (Orphan tracking).

Если какой-то из пунктов горит красным (**FAILED**), следуйте рекомендациям в поле `Details`.

## 🧪 9. Тестирование и контроль качества

Для обеспечения стабильности при внесении изменений в плагин используется система автоматизированного тестирования на базе **Unity Test Framework (NUnit)**.

### Расположение тестов:
Все тесты находятся в папке: `plugin/Editor/Tests/`.

### Основные тестовые наборы:
*   **HandlerTests.cs**: Проверяет логику обработки отдельных элементов (текст, изображения, кнопки).
*   **AdaptiveLayoutTests.cs**: Тестирует корректность маппинга констрейнтов в анкоры и работу `CanvasScaler`.
*   **ConstraintsMappingTests.cs**: (Новое в v2.5.1) Глубокая проверка всех математических комбинаций Figma Constraints.
*   **FigmaImportTestRunner.cs**: Интеграционные тесты для проверки процесса сборки иерархии.

### Как запустить тесты:
1.  В Unity откройте окно: **Window -> General -> Test Runner**.
2.  Переключитесь на вкладку **EditMode**.
3.  Нажмите **Run All**, чтобы запустить все тесты плагина.
4.  Убедитесь, что все тесты горят зеленым перед созданием Merge Request.

> [!IMPORTANT]
> При добавлении новых маркеров (например, для новых UI-компонентов) обязательно добавляйте соответствующий тест в `HandlerTests.cs`.
