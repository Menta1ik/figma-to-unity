# Концепция развития UI-пайплайна (Figma -> Unity) v2.3.0: Production-Ready Vision

## 🎯 Общая цель
Трансформация текущего импортера из инструмента прототипирования в полноценную производственную систему. Ключевые задачи: сохранение игровой логики при итерациях дизайна, интеллектуальное управление ресурсами и автоматизация типографики.

**Технологический стек:** Строго **uGUI (Unity UI)** на базе Canvas. Все элементы создаются как `RectTransform`, `Image`, `TextMeshProUGUI` и стандартные компоненты Unity UI. Использование UI Toolkit (Elements) исключено.

---

## 1. Архитектурный фундамент: Система «Паспортов» (FigmaElement)
Для реализации неразрушающего обновления внедряется компонент-метка `FigmaElement.cs`.
*   **Назначение:** Связывание GameObject в Unity с уникальным `node_id` из Figma.
*   **Состав данных:**
    *   `string figmaNodeId`: Постоянный идентификатор слоя.
    *   `string nodeType`: Тип узла (FRAME, TEXT, и т.д.).
    *   `string lastUpdateHash`: Хеш параметров для быстрой проверки изменений.
*   **Логика:** При первой сборке объект получает паспорт. При повторной — плагин ищет объект по ID, а не создает новый.

---

## 2. Модуль Smart Sync (Алгоритм Diffing)
**Проблема:** Полное удаление Canvas уничтожает скрипты, анимации и связи. 
**Решение:** Точечное обновление свойств и политика Non-Destructive Update.
*   **Процесс обновления:**
    1.  **Match:** Обновление только визуальных параметров (`RectTransform`, `Image.color`, `TMP.text`) у существующих объектов.
    2.  **Protect (Non-Destructive):** Кастомные имена объектов в Unity и навешенные пользователем скрипты (`Button`, `AudioSource`, `AntigravityLogic`) строго защищены от удаления или перезаписи при реимпорте.
    3.  **Create:** Создание новых элементов, добавленных в макет.
    4.  **Soft Delete:** Объекты, удаленные в Figma, помечаются префиксом `[DELETED]` и деактивируются в Unity. Это предотвращает критические ошибки Missing Reference в логике.

## 3. Модуль Shared Assets Resolver
**Проблема:** Дублирование одинаковых текстур (кнопок, иконок) в разных окнах. 
**Решение:** Глобальный поиск ресурсов.
*   **Механика:**
    1.  Задается путь **Shared Assets Path** (например, `Assets/UI/Shared/`).
    2.  Перед скачиванием спрайта плагин ищет файл с таким же именем или хешем в папке Shared.
    3.  Если ресурс найден — используется существующая ссылка. Если нет — ресурс загружается в локальную папку окна.
*   **Требование к дизайну:** Соблюдение единого нейминга для повторяющихся элементов в Figma.

---

## 4. Интеллектуальная Типографика (Typography Sync)
**Проблема:** Несовпадение визуальных стилей текста и ручная настройка TMP. 
**Решение:** Автоматический маппинг и математический пересчет.
*   **Font Mapping Table:** Таблица сопоставления семейств шрифтов Figma (например, `Inter-Bold`) с ассетами `TMP_Font Asset`.
*   **Авто-конфигурация:** Перенос размера, цвета, выравнивания и настроек регистра (All Caps).
*   **Line Height Math:** Автоматический пересчет межстрочного интервала из пикселей Figma в проценты Line Spacing для TextMesh Pro:
    *   `lineSpacing = (lineHeightPx / fontSize) * 100 - 100`

---

## 5. Функция Reskin (Theme Duplication)
**Проблема:** Трудоемкость создания скинов и похожих окон. 
**Решение:** Клонирование структуры с подменой арта.
*   **Сценарий:** Разработчик выбирает настроенный префаб (например, «Магазин брони») и указывает новый фрейм в Figma («Магазин оружия»).
*   **Результат:** Создается копия префаба, в которой плагин автоматически обновляет все спрайты и цвета по ID, сохраняя всю внутреннюю логику и ссылки на скрипты.

## 6. Сервис-ориентированная архитектура (v2.3)
**Проблема:** Монолитный `FigmaParser` становится трудноподдерживаемым при добавлении новых фич.
**Решение:** Разделение ответственности.
*   **Службы:** Внедрение независимых сервисов (`Service Pattern`) для работы с сетью, файловой системой и префабами. Это позволяет изолированно тестировать и обновлять компоненты системы.
*   **Кэширование:** Использование контекстных хранилищ данных для предотвращения избыточных вычислений.

## 7. Интерактивный слой (Interactive Pipeline)
**Проблема:** Импортируемый UI статичен, требует ручного развешивания базовых компонентов (`Button`) и порождает "Raycast Hell". 
**Решение:** Анализ маркеров имени и оптимизация графов Raycast.
*   **InteractiveHandler:** Отдельный модуль, который парсит префиксы/суффиксы узлов из Figma (например, `[Btn]`, `[Scroll]`). Если маркер найден, плагин автоматически генерирует нужный Unity UI компонент (`Button`, `ScrollRect`).
*   **Raycast Optimization:** По умолчанию все графические элементы импортируются с `Raycast Target = false`. Галочка включается автоматически только для текстовых слоев и интерактивных компонентов, экономя ресурсы CPU.

## 🛠 Техническое резюме для ИИ-агентов (Analysis Prompt)
1.  **Интеграция Figma API:** Использование персонального токена доступа для прямого парсинга JSON.
2.  **Asset Management:** Реализация логики поиска через `AssetDatabase.FindAssets` перед инициацией загрузки.
3.  **UI Construction:** Переход от `new GameObject()` к поиску через `GetComponentsInChildren<FigmaElement>()`.
4.  **Error Handling:** Вывод предупреждений в консоль Unity при отсутствии шрифтов в таблице маппинга.
