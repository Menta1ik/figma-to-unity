# 🧠 Технические концепции: Figma Importer v2.8.0

Этот документ объясняет архитектурные принципы и ключевые механизмы, которые делают Figma Importer v2.8.0 самым стабильным инструментом для Unity.

---

## 1. Система "Паспортов" (FigmaNodeId)

В основе системы "умной синхронизации" (Smart Sync) лежит концепция уникальных идентификаторов.

### Как это работает:
*   Каждый объект в Figma имеет уникальный `id` (например, `12:345`).
*   При импорте этот ID записывается в компонент `FigmaElement` на стороне Unity.
*   При **повторной синхронизации** плагин не просто создает новые объекты, а ищет в иерархии Unity объект с соответствующим ID.

### Почему это критично:
1.  **Сохранение компонентов**: Если вы добавили на кнопку свой скрипт `MyFancyAnimation.cs`, при обновлении верстки плагин найдет этот объект и обновит только его визуальные параметры (`Image`, `RectTransform`), сохранив ваш скрипт.
2.  **Ручное переименование**: В настройках (`FigmaImporterSettings`) можно включить опцию `Preserve Unity Names`. В этом случае, даже если вы переименовали "Button" в "Login_Submit_Btn" в Unity, плагин узнает объект по ID и не будет возвращать ему имя из Figma.

## 2. Orchestrator Consolidation (v2.8.0)

В версии **v2.8.0** мы устранили проблему "раздвоенного мозга" (Double Brain). Теперь вся логика — от сетевого запроса до сохранения префаба — централизована в `FigmaParser`.

```
FigmaImporterWindow (UI Layer)
  └── FigmaParser (Single Brain / Orchestrator)
        ├── FigmaAPIClient       — сетевые запросы и ошибки
        ├── FigmaResponseCache   — файловый кеш JSON
        ├── FigmaTreeWalker      — обход дерева и создание GO
        ├── ImageSyncService     — BATCHING загрузка изображений
        └── FigmaMaskResolver    — жизненный цикл масок
```

**Результат**: Окно импорта стало "тонким клиентом", делегируя всё выполнение оркестратору. Это гарантирует, что кэширование и диагностика работают одинаково во всех режимах (Full Sync, Reskin, Font Audit).

## 3. Batching Engine (v2.8.0)

Ключевое нововведение версии 2.8.0, решающее проблему **HTTP 414 URI Too Long**.

### Проблема:
При импорте больших макетов (100+ изображений) суммарная длина ID всех нод в одном GET-запросе превышала лимит сервера Figma (около 8KB). Это приводило к сбросу соединения и пустой сцене.

### Решение:
`ImageSyncService` теперь автоматически разбивает список изображений на "пачки" (batches) по **25 штук**. 
1. Плагин собирает все ID нод, требующих скачивания.
2. Разрезает список на сегменты.
3. Делает последовательные запросы ссылок для каждого сегмента.
4. Объединяет результаты в единый пул для параллельного скачивания.

## 4. Offline Mode & Local JSON (v2.8.0)

Для работы в условиях ограниченного интернета или с заранее подготовленными данными внедрен **Offline Mode**.

*   **Приоритет**: Если включен флаг `Use Local JSON`, плагин игнорирует API и ищет файл по пути `Assets/lobby_figma.json`.
*   **Совместимость**: Структура локального JSON должна полностью соответствовать ответу Figma API v1 (включая контейнеры `nodes` или корень `document`).

## 5. Improved API Diagnostics (v2.8.0)

Мы отказались от "молчаливых выходов" (Silent Exits). 

*   **Network Errors**: Любая ошибка `UnityWebRequest` (401 Unauthorized, 404 Not Found, 414 URI Too Long) теперь выводится в консоль с расшифровкой и полным URL запроса.
*   **Structure Guard**: Если JSON пришел, но в нем нет подходящих нод для импорта, `FigmaParser` выдает явное предупреждение.

## 6. API Response Caching

Каждый sync ранее делал полный запрос к Figma API. Теперь используется файловый кеш в `Library/FigmaCache/`.

### Алгоритм:
1. **Лёгкий запрос**: `GET /?fields=version` — только версия файла.
2. **Cache HIT**: Если версия совпадает → чтение JSON с диска.
3. **Cache MISS**: Полный запрос → сохранение нового JSON и версии.

## 7. Modular Handlers (Workers)

Парсинг каждой ноды делегируется специализированным обработчикам:
*   **TransformHandler**: Позиция, размер, Pivot, Anchors.
*   **LayoutHandler**: Auto Layout (Layout Groups, Content Fitter).
*   **TextHandler**: TMP, шрифты, выравнивание.
*   **ImageHandler**: Загрузка спрайтов, 9-slice.
*   **InteractiveHandler**: Кнопки, переключатели (BETA).

## 8. Adaptive Layout & Constraints Mapping

Для реализации адаптивности плагин преобразует систему **Constraints** из Figma в настройки **Anchors** и **Offsets** компонента `RectTransform`.

### Как работает маппинг:
1.  **LEFT / TOP**: Анкоры устанавливаются в `0` (или `1` для верха). Смещение (`offset`) фиксируется относительно родителя.
2.  **RIGHT / BOTTOM**: Анкоры устанавливаются в `1` (или `0` для низа). Расстояние рассчитывается от края родительского контейнера.
3.  **CENTER**: Анкоры устанавливаются в `0.5`. Объект позиционируется относительно центра родителя.
4.  **STRETCH (LEFT_RIGHT / TOP_BOTTOM)**: Анкоры растягиваются от `0` до `1`. Значения `RT.offsetMin/Max` сохраняют отступы (padding) от краев.
5.  **SCALE**: Анкоры устанавливаются в процентном соотношении от размера родителя (от `0` до `1`).

## 9. Stencil Guard & Hierarchy Flattening

В версии 2.5.2 мы решили критическую проблему Unity с переполнением буфера трафарета (Stencil Buffer).

### Механизмы защиты:
1.  **DismantleAllMaskContainers**: Перед каждым импортом плагин находит технические контейнеры `[Mask]` и «разбирает» их, возвращая объекты в общую иерархию. Это предотвращает бесконечное наслоение масок при повторных синхронизациях.
2.  **Глубина вложенности**: Плагин отслеживает уровень вложенности масок. Если глубина превышает **3**, следующая маска автоматически преобразуется в `RectMask2D`.
3.  **Auto-Fallback**: Простые прямоугольные маски или маски с высокой вложенностью автоматически заменяются на `RectMask2D`, что экономит Draw Calls и предотвращает ошибку `stencil mask depth > 8`.

## 10. Система Soft-Delete (Orphan tracking)

Что происходит, когда вы удалили кнопку в Figma и запустили синхронизацию?

### Режим Non-Destructive:
Плагин не удаляет объекты в Unity "втихую". Вместо этого:
1. Объект помечается как "сирота" (Orphan).
2. Ему добавляется компонент `FigmaOrphanedElement`.
3. В консоль выводится предупреждение.

Это защищает вас от случайной потери логики, которая могла быть привязана к удаленным элементам. Вы сами решаете, когда окончательно удалить объект из сцены.

## 11. Fill Container — layoutGrow

В Figma Auto Layout дочерний элемент с `layoutGrow = 1` означает «заполни всё свободное пространство по главной оси» (Fill Container).

### Как это работает в плагине:
1.  Поле `layoutGrow` десериализуется из API.
2.  В методе `ApplyLayoutGrow()` плагин:
    *   Проверяет `layoutMode` родителя (HORIZONTAL/VERTICAL).
    *   Добавляет `LayoutElement` на объект.
    *   Устанавливает `flexibleWidth = layoutGrow` или `flexibleHeight = layoutGrow`.
